# Decisions

- 2026-11-11 — crate and binary are named soundglass — free on crates.io, apt and Flathub; the app's final name is still open (user's choice)
- 2026-11-11 — licence GPL-3.0-or-later — same as lightview, so its code can be copied over (user's choice)
- 2026-11-11 — eframe 0.37 (glow, wayland, x11, accesskit) for the UI — carried over from lightview (user's choice)
- 2026-11-11 — symphonia with all codecs for decoding — pure Rust, MPL-2.0 (user's choice)
- 2026-11-11 — cpal with default features (ALSA on Linux) for sound output — Apache-2.0 (user's choice)
- 2026-11-11 — no resampling in the spike; the device must accept the file's rate — PipeWire and PulseAudio accept any rate; rubato comes in milestone 2, before Windows (user's choice) — changed 2026-11-11: the device now opens at its own rate and rubato converts
- 2026-11-11 — std mpsc sync_channel of Vec<f32> between decoder and audio callback, no ring-buffer crate — no new dependency; accepted limit: memory is freed inside the audio callback — changed 2026-11-11: replaced by in-memory tracks the callback reads by chunk
- 2026-11-11 — audio starts before the window opens — decoding and device setup overlap OpenGL setup, as lightview does for images
- 2026-11-11 — "first sound" is timed when the first real samples reach the cpal callback — the device's own output latency is not included
- 2026-11-11 — sound is held (device outputs silence) until the window's second frame, i.e. after eframe makes it visible; it keeps playing when minimized (user's choice) — changed 2026-11-11: now done by sending Cmd::Play on that frame instead of an atomic flag
- 2026-11-11 — new dependencies rubato, rfd, image (jpeg, png only) and eframe's persistence feature for milestone 2 — all MIT or MIT/Apache-2.0 (user's choice)
- 2026-11-11 — loudness (LUFS) is measured by our own BS.1770 code, no ebur128 crate (user's choice)
- 2026-11-11 — playback speed changes pitch for now (tape style); the user's own pitch-preserving algorithm replaces it later, in the resampler stage (user's choice)
- 2026-11-11 — whole track decoded into memory; later a RAM limit in Settings decodes only a segment of very long files, with a warning that has "Don't show again" (user's choice)
- 2026-11-11 — tracks are stored as fixed 65 536-frame chunks of Arc<[f32]> behind a Mutex the callback only try_locks — the callback never blocks or copies the list, and seeks are instant
- 2026-11-11 — the audio callback owns all playback state (Engine); the UI sends Cmds over mpsc and reads atomics; retired tracks are freed on the UI thread
- 2026-11-11 — the device opens once at its default rate and channels; one rubato sinc resampler (128 taps, ratio 1/10 to 10) does rate conversion and speed together
- 2026-11-11 — no gapless code of our own — symphonia 0.6's decoders already trim encoder delay and padding
- 2026-11-11 — a decode thread stops when only it still holds the track — moving on to another file must not keep decoding the old one
- 2026-11-11 — waveform from per-1024-frame min/max peaks collected while decoding, drawn as one line per pixel column — cheap to redraw every frame, and it fills in as the file decodes
- 2026-11-11 — milestone 1.5 "Usable player" goes before the rest of milestone 2: phone-shaped minimal UI, previous/next, default app (user's choice)
- 2026-11-11 — three buttons (previous, play/pause, next) plus a top menu bar for future tools (user's choice)
- 2026-11-11 — Previous restarts the track after 3 s of play, otherwise goes to the previous file, as Spotify does
- 2026-11-11 — the next file in the folder is decoded once the current one is in memory and queued, so Next is instant and the end of a song flows into the next one
- 2026-11-11 — no .opus in the folder list or the default-app types — symphonia 0.6 has no Opus decoder
- 2026-11-11 — WAV INFO tags are not shown — symphonia 0.6.1 reads the INFO chunk but drops it (wave/mod.rs builds WavReader from opts.external_data.metadata); ID3, Vorbis comments and MP4 tags work
- 2026-11-11 — the cover is decoded on its own thread and shrunk to at most 512 px — a large embedded JPEG must not delay the first sound or the UI
- 2026-11-11 — the waveform leaves the main view; its drawing code stays in git (a61e538) and track peaks are kept for the later editing view
- 2026-11-11 — transport icons and the placeholder note are drawn with egui shapes, not font glyphs — they render the same whatever fonts are installed
- 2026-11-11 — Space toggles playback only when no widget has focus — a focused button already takes Space as its own click
- 2026-11-11 — settings live in settings.txt (key=value) in eframe's storage folder, read before the window opens and written atomically; "Remember window size" (default off) switches eframe's persist_window — no serde/ron until settings grow — changed 2026-11-11: soundglass now stores the window size itself (see below); persist_window is always off
- 2026-11-11 — started without a file (from the app menu), soundglass shows the Open dialog first and quits if it is cancelled; an empty start window can come later
- 2026-11-11 — soundglass.desktop's MimeType line is the single list of claimed formats; install.sh reads it for xdg-mime, so the two cannot drift
- 2026-11-11 — UI fonts copied from lightview (Roboto and Droid Sans Mono, Apache-2.0; emoji-icon-font, MIT) with their licence files in fonts/ — eframe without default features has no fonts, and egui's default set is not clearly GPL-compatible; no CJK font yet (user's choice)
- 2026-11-11 — default window 380 × 680 points, 100 shorter than first planned (user's choice)
- 2026-11-11 — volume is a small speaker button left of Previous that pops up a slider (user's choice); gain is the slider position cubed, not saved between runs
- 2026-11-11 — speed lives in Playback → Change speed ▸ with presets and Custom… in steps of 0.05 (user's choice)
- 2026-11-11 — waveform comes back as a View → Waveform toggle in place of the seek bar line, off by default and remembered in settings.txt (user's choice)
- 2026-11-11 — loudness is measured on the decode thread after decoding, from the in-memory chunks; peak is the sample peak taken from the waveform peaks (no true-peak oversampling)
- 2026-11-11 — K-weighting coefficients come from the BS.1770 analogue prototypes for any rate (as libebur128 does); tests check the standard's −3.01 LUFS reference at 44.1 and 48 kHz
- 2026-11-11 — Track Info's bitrate is the average (file size × 8 ÷ length), tags included — simple and right for VBR files too
- 2026-11-11 — Open Recent lists files opened at startup or through Open…, not each Next; stored in eframe storage as lines, as lightview does
- 2026-11-11 — Track Info is a right side panel like lightview's inspector; opening it widens the window by the panel and closing it shrinks it back, so the player keeps its size (user's choice)
- 2026-11-11 — "Remember window size" stores the whole window (panel included), whether Track Info is open and its width, so a restart comes back coherent (user's choice)
- 2026-11-11 — no eframe window persistence — eframe 0.37 saves the window only if persist_window was on at start, restores a saved one even when it is off, and knows nothing of the panel; App::save blanks its "window" entry so a stale size is never restored
- 2026-11-11 — maximized or fullscreen frames are not recorded as the window size, and Track Info does not resize a maximized window
- 2026-11-11 — the window size is read from ctx.viewport_rect(), not viewport().inner_rect — egui-winit builds inner_rect from the window position, which Wayland never reports, so it is always None there
- 2026-11-11 — the cover is sized from the controls' height measured on the previous frame, not a fixed guess — a fixed 190 pt pushed the buttons out of wide windows; it settles in one extra frame
- 2026-11-11 — milestone 3 is done whole, with an Edit panel that widens the window; click seeks, drag selects; Play stops at the selection's end, with a Loop toggle (user's choice)
- 2026-11-11 — edits are a list of pieces of the original track (frames or silence), not copies of the audio — an edit costs nothing, undo keeps old lists, the decoded audio never changes
- 2026-11-11 — cut, crop and silence only once the track is fully decoded — the edit list never points at audio that isn't there yet
- 2026-11-11 — an edited track does not move on gaplessly into the next file; playback stops at its end — the edits must not be left behind unsaved without a word
- 2026-11-11 — Save As writes WAV, FLAC, MP3 and Ogg Vorbis, not Opus — symphonia can't play Opus back; new dependencies hound, flacenc, mp3lame-encoder, vorbis_rs and lofty approved (user's choice)
- 2026-11-11 — leaving a file or quitting with unsaved edits asks Save As / Discard / Cancel (user's choice)
- 2026-11-11 — the Edit panel is a bottom panel that grows the window by its height, like Track Info does by its width; zoom is Ctrl+scroll and −/+/Fit buttons, not Ctrl+0/+/− — egui already uses those keys for the UI's own zoom — changed 2026-11-11: the wheel zooms and right-drag pans (see below)
- 2026-11-11 — both waveforms draw through edit::min_max: peaks for long spans, the samples themselves for short ones — zoomed-in edges are exact and the strip and panel always agree
- 2026-11-11 — undone back to the first step, the player gets no edit list, so the track moves on gaplessly again; Cut leaves the playhead at the cut, Crop at 0, Silence keeps the selection
- 2026-11-11 — the unsaved-edits prompt is raised in go() and open() (every way of leaving a track goes through them) and on the window's close request
- 2026-11-11 — Save As encodes on its own thread to a hidden temp file next to the target, copies the tags, decodes it back (rate, channels and length within 0.1 s), then renames it into place; a target that is the original (by canonical path) is refused; any failure or panic removes the temp file
- 2026-11-11 — tags are copied with lofty from the original's primary tag, or its first one (the test album has only ID3v1), re-mapped to the target format's main tag type; a save whose tags can't be copied still succeeds and says so
- 2026-11-11 — after Save As the view stays on the original with its edits, now counted as saved; the save runs on a copy of the edit list, so editing on while it saves is safe
- 2026-11-11 — no dither when saving to 16 or 24 bits — simple, and inaudible for music at normal levels
- 2026-11-11 — MP3 is constant bitrate only (128–320 kb/s), mono or stereo at LAME's rates (up to 48 kHz); anything else is refused with a message, not resampled
- 2026-11-11 — the MP3 encoder is flushed with padding (FlushGap) and its LAME tag frame overwrites LAME's empty first frame — that tag holds the delay and padding, so the saved file decodes to the exact length; FlushNoGap drops the last ~2000 frames
- 2026-11-11 — flacenc's STREAMINFO is patched so its minimum block size leaves out the shorter last block, as the FLAC spec says — otherwise symphonia 0.6 can't open the file (ffmpeg can)
- 2026-11-11 — Save As defaults to FLAC 16-bit; Ogg Vorbis quality is 0–10 as oggenc counts (default 6)
- 2026-11-11 — the playhead is drawn where playback is now: the callback stores when it last set the position, and the UI moves it on by the time since (wrapping in a looped region), repainting every frame while playing with a waveform shown — a 250 ms repaint and 10–20 ms position steps made it jump when zoomed in
- 2026-11-11 — waveform columns are cached per waveform and worked out again only when the width, view, edits or decoded length change; min_max reads samples only below 1024 frames per column — the waveform lagged when every frame re-read up to millions of samples
- 2026-11-11 — in the Edit panel the wheel zooms around the pointer and right-drag (or sideways scrolling) pans; Cut is named "Cut out" (user's choice)
- 2026-11-11 — zoomed in, the view turns the page only when the playhead crosses its right edge, so a view panned away from the playhead stays put
